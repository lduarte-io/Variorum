Direction A — Index · the book page, for one note

The job it claims

Getting around a long note. The index is the note’s table of contents: markdown headings become sections, everything else nests under them.

What fills the window

The note itself, rendered, on the right — selected block washed, scroll-synced. Nothing is empty at any window height.

What it trades

Half the width goes to navigation, so it is the weakest of the three for actually reading. Notes with no headings get a flat index.

Formatting in Variorum is markdown, and that is not a detail of the implementation — it is the whole design.

The vocabulary is small on purpose: bold (⌘B), italic (⌘I), struck out, and inline code.

Headings are sizes

A line that starts with #, ## or ### is a heading — those three, and nothing else.

  • Lists are lines that start with “- ”
  • Format ▸ Bullet List makes one from the line you’re on
  • Select several lines and it makes them all into a list
  • ☐And a checkbox is a list item with a box: - [ ]
  • ☑CLICK the box to tick it — that is an ordinary edit, so ⌘Z takes it back and a sealed note refuses it

Direction B — Read · the note as a page, with reading tools

The job it claims

Reading your own note as a reader would — the calm page, the boundaries gone, the markdown rendered. Block 11’s promise, kept.

What fills the window

The page. Reading tools ride a small floating rail; block doors live in the margin and only wake on hover, so at rest there is nothing but prose.

What it trades

Navigation is a popover (contents ▾) rather than a standing column, and it is the least useful of the three for rearranging a note.

Direction C — Blocks, kept and earned · the workbench

The job it claims

Working on the blocks as objects: select several, move them, tag them, see which carry takes, comments or locks — the thing today’s page gestures at and doesn’t do.

What fills the window

Real information per row, plus a right panel for the selected block (its takes, comments, lineage) — the same context panel Act 10 item 10 gives the library.

What it trades

It is a management surface, not a reading one — it answers “why would someone use this” with power, not calm. Keeps the name, so candidate (c) doesn’t apply.

Item 17 — Snippets, the bounded refresh

The ownership answer, in the structure

The rail lists the snippet groups as flat siblings — nothing nested under a book or a note, because nothing owns them. “field guide” sits beside “Snippets” as an equal, which is what it actually is.

The four new doors

+ new group · rename/delete a group (its ⋯) · move snippets between groups (bulk bar and row ⋯) · search, scoped by the rail — “All snippets” searches across every group.

Naming

Every string says snippet; “pool” appears nowhere. The one word I had to choose is group for a container — that’s product vocabulary, so it’s yours: group / set / box / shelf.
