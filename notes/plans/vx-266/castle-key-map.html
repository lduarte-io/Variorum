Castle key map

What each key is, where it lives, what it's locked with, and what the server holds — today, and in the new design (your rulings of 2026-10-13: retire the Apple key on entering Castle; the key history under today's key). A companion to second-opinion.html. Every name below is the design's; nothing here is built yet.

The whole idea in two lines. In Castle, your Apple account opens nothing of this library — not the library, not any copy Variorum ever made of it. In Standard, it opens your library and every copy Variorum made of it. In Castle = safe. Out of Castle = not safe.

The cast

Every key is a random 256-bit number except your passphrase and words, which you hold. A locked copy is one key locked with another; the padlock's colour says which key opens it. Nothing on the server — and nothing in a key file — opens anything by itself.

How to read the maps

Each map has the same four places: you, this Mac (its Keychain, the library's folder, the backups folder), Apple (iCloud Keychain and iCloud Drive), and the Variorum server. Red outlines are today's gaps. Struck-out, dashed chips are keys that don't exist or no longer open anything. Use the buttons to light up what each kind of intruder could open — the rest fades.

The new design

Three changes do most of the work: the mode is recorded, not guessed from where keys sit; each key has its own Keychain item, so opening one copy never disturbs another; and each library's older keys travel with it, locked under today's key. Your D3 ruling adds the fourth: entering Castle deletes the Apple key.

Castle — the new design

  • On this Mac: Touch ID (or the passphrase) opens the library — and, through the history, every older copy, nothing typed.
  • On a new Mac: your passphrase or words; the newest backup's history opens every older one.
  • Lose the passphrase, the words and every Touch ID copy: the library and its older copies are gone. That's the promise, said at the door — export a plain copy first if you want one.

Standard — the new design

  • On this Mac: the silent copy — nothing asked.
  • On a new Mac: your Apple account brings everything back, nothing typed.
  • What it means: your Apple account — and anyone with this Mac's login password — can open the library and every copy Variorum keeps. Out of Castle means not safe, said plainly.

The key history

This is what makes backups simple: a backup made under an older key opens through today's key, on your Mac, with nothing typed — and on a new Mac, the newest backup's history opens every older backup once you type your passphrase or words. It's also why W-1 disappears: the old key from the "only this Mac" days rides forward in the history.

Moving between them

Entering Castle (new design)

  1. You type your passphrase and twelve words (they're set now if you have none). The screen says plainly: lose them and every Touch ID copy, and this library and its older copies are gone — export a plain copy first if you want one.
  2. Synced only: a new master M and sync key C are made, your writing on the server is re-encrypted with the new C, and the vault is rewritten with no Apple copy.
  3. A new library key L′ is made, and it locks the old one — the old key joins the history.
  4. The library file is re-encrypted with L′. The one key file now holds L′ · locked with P L′ · locked with W (and L′ · locked with M if synced) — no Apple lock.
  5. L′ goes into the Touch ID copy (or nowhere, with Always ask); the silent copy is deleted.
  6. A fresh backup is made under L′.
  7. The Apple key is deleted from iCloud Keychain. That reaches every device, with no recovery — so every older copy's Apple lock is dead, wherever the copy is: iCloud Drive, Time Machine, a USB stick.
  8. Synced: each of your other devices asks for your passphrase once, gets the new keys, re-encrypts its own library, and deletes its own Apple key too.

Leaving Castle (new design)

  1. You confirm with Touch ID or the passphrase, after the plain warning: your Apple account — and anyone with this Mac's login password — will be able to open this library and every copy Variorum kept of it, including copies made while you were in Castle.
  2. A fresh Apple key is made in iCloud Keychain, with a new id. Only this device makes it; your other devices wait for it to arrive.
  3. The key file gains L · locked with A; synced, the vault gains M · locked with A.
  4. L moves from the Touch ID copy to a silent copy.
  5. Your other devices follow without asking you anything; each adds its own Apple lock when the new key arrives.

Another device follows (synced)

  1. Another of your devices entered Castle (or replaced the keys). This device notices the vault changed.
  2. It asks for your passphrase or words — once.
  3. It gets the new M and C, re-encrypts its own library with a new key, puts the old key in the history, and deletes its own Apple key.
  4. Until you type it, this device still opens and you can write; it just doesn't sync, and a banner says why.

Opening an older backup

Today (VX-209). The backup's own Apple lock opens it silently; this Mac's one Keychain slot for the library is overwritten with the backup's key; the Touch ID copy is deleted; the library is now Standard. Bringing your Castle library back finds the silent slot and stays Standard.
New design.
  1. Inside Variorum (already unlocked), you pick an older backup.
  2. Its key is found through the history — today's key opens the older ones — so nothing is typed. (A backup from another Mac opens with your passphrase or words.)
  3. The copy is re-encrypted with today's key straight into place; the library you had is kept with your older libraries.
  4. Your library is back as it was then — in the mode it's in now. A Castle library stays in Castle.

Signing in and out, other accounts

The library records which account it belongs to; signing in or out never changes its mode. Signed in as a different account, nothing syncs until you choose to move the library there (with that account's mode, asked first). Your new writing always belongs to the library's account, never to whoever happens to be signed in.

What changes from today, in one list

  • The Apple key is deleted when a library enters Castle, and every copy's Apple lock dies with it (VX-301).
  • Apple keys are named by their own id — one per library or sync account — and only one device ever makes each, so two devices can't race to make the same one.
  • One key file per library, carrying the history; no more "the newest file wins".
  • One Keychain item per key (silent or Touch ID), never one slot shared by every copy of the library.
  • The mode is recorded (inside the library, where only its key can change it) and remembered by this Mac; opening a copy never lowers it.
  • Plans for long acts and settings that could weaken protection are sealed with the library's key, so a planted or edited file is caught.
  • Backups belong to a library and a Mac, so two Macs sharing an iCloud Drive folder never prune each other's (VX-302).
