## Ground rules

- Queries are read-only: plain `fetch` functions over `Database` plus `ValueObservation` publishers over `AppDatabase`. No business rules beyond the documented read-time fallbacks; anything smelling like a mutation belongs in Operations.
- **Missing-row tolerance is a correctness requirement, not defensive style** (SyncSpec §5): a placement whose block hasn't arrived renders as a gap; a `chosen_variant_id` pointing at nothing falls back; a `grouping_tag_id` pointing at a tombstone means ungrouped. Every query gets at least one missing-row test.
- **P1 is asserted, not hoped:** the benchmark harness measures each core query at two corpus sizes (e.g. 1k and 10k blocks) and asserts near-flat scaling for viewport-shaped reads (post render, timeline page). Absolute timings are machine-noise; *ratios* are the assertion.
- P2: all observation delivery off the main thread is GRDB's default; assert no query API takes a blocking connection on the caller's thread.

## Steps

### Step 1 — Post render (the one everything else stands on)
**Files:** `Sources/VariorumCore/Queries/PostRender.swift`, tests.
**Work:** `renderPost(db, containerID) -> [RenderedBlock]` — walk `container_block` by `(position, id)`, resolve each slot's variant by the read-time rule (chosen live+active → default live → gap), return block id, variant id, text, fan badge data (live active variant count > 1), lock flags. One indexed query (JOINs, no N+1). A `renderedText(db, containerID) -> String` join for export/diff callers (blocks joined by `"\n\n"` — the rendering join that re-creates stored-nothing separators; decided here, document for the author).
**Tests:** order; fallback matrix (NULL/tombstoned/archived chosen); missing block row (gap, no crash); fan badge counts; pool renders the same way.

### Step 2 — Reading assembly
**Files:** `Queries/ReadingAssembly.swift`, tests.
**Work:** `assembleReading(db, readingID) -> [ReadingEntry]` — curated: `reading_post` by `(position, id)`; smart: interpret `query_spec` JSON (define the v1 predicate vocabulary: tag paths, profile, date ranges — smallest useful set, documented); apply `sort_field`/`sort_dir` (manual only for curated); `max_posts` extent; grouping by `grouping_tag_id` subtree (dangling ⇒ ungrouped, the AppSpec §7 rule). Entries carry post id/title/entry_date + section key.
**Tests:** curated order + extent; each sort field; smart predicate basics; grouping incl. dangling tag; tombstoned posts excluded; a post in many readings.

### Step 3 — Lineage & diff inputs
**Files:** `Queries/Lineage.swift`, tests.
**Work:** recursive CTE over `edge` (`derived_from`): `ancestors(of block)`, `descendants(of block)`, depth-bounded; `versionPeers(of post-block?)` — no: `version_of` links blocks; expose `versionOf(blockID)` pairs. Diff inputs: `diffPair(variantA, variantB) -> (String, String)` (just the two buffers; whitespace normalization is a view toggle, Phase 11). Outline mapping: `derivedBlocks(fromOutlineBlock)` is the same descendants query filtered by container.
**Tests:** chains (extract→divide lineage from Phase 3 fixtures), cycles impossible but bounded anyway, dead endpoints filtered (edges may outlive an endpoint — read filters by live blocks, the documented sweep exception).

### Step 4 — Tags, timeline, pool, tray, unplaced
**Files:** `Queries/TagQueries.swift`, `Queries/Timeline.swift`, `Queries/PoolAndTray.swift`, tests.
**Work:** tag subtree by path prefix (live rows); "everything tagged X" = UNION of post_tag/block_tag (AppSpec §7 note); timeline: posts by `entry_date` / `last_major_revision_at` / `last_touched_at` with keyset pagination (viewport-shaped — never OFFSET over the corpus); pool listing (pool container render + block tags); **the tray (owns the KnownIssues entry):** per-post tray = tombstoned blocks with `last_container_id = post` (individually deleted there) — container-cascade victims are `restoreContainer`'s business and excluded by definition; resolve the entry. Unplaced-blocks utility query (live blocks, no live placement) — cheap, lands here even though its view is Phase 11.
**Tests:** subtree correctness after renameTag; UNION dedupe; pagination window math; tray lists exactly the individually-deleted; unplaced population after divideW/merge.

### Step 5 — ValueObservation wiring
**Files:** `Queries/Observations.swift`, tests.
**Work:** `AppDatabase.observePost(containerID)`, `observeReading(readingID)`, `observeLibrary(sort:)` etc. — ValueObservation over the Step 1–4 fetch functions, delivering on a background queue, distinct-until-changed on the projected values. Keep projections value-typed and small (IDs + text), per the store-IDs-not-copies rule… note: rendered text in a projection is a *projection*, allowed — never a second source of truth.
**Tests:** an op through Operations triggers exactly the affected observation; unrelated writes don't fire it (region-scoped observation).

### Step 6 — Corpus & benchmarks (P1/P2 proven)
**Files:** `Tests/VariorumCoreTests/Support/CorpusFactory.swift`, `PerfBenchmarkTests.swift`.
**Work:** seeded deterministic corpus builder (N posts × M blocks, journals + a book-shaped reading, some fans/lineage/tags — through Operations, so it doubles as a scale smoke test); benchmarks: post render, reading assembly first page, timeline page, tag subtree — each at 1k vs 10k blocks, asserting time ratio stays near-flat (define tolerance, e.g. < 3× for 10× corpus); autosave cost flat in post length. Mark the suite `.serialized`/`.tags(.perf)` so ordinary runs stay fast if needed.
**Tests:** the benchmarks are the tests.

### Step 7 — Closeout
Ritual per CLAUDE.md: results here, master plan table + pointer, resolve the tray KnownIssues entry, **write the Phase 5 (sync core) plan + kickoff** from `notes/SyncSpec.md` §10 (mirrored schema, push/pull engine, apply mode, merge matrix, repairs, two-client convergence suites, the empty-outbox-after-push assertion from SyncSpec §4).

## Explicitly out of scope
Any UI (views arrive Phases 10–11). Sync engine (5). Markdown export (11, needs this layer — note the door). Editor integration (7). New operations.

## Risks / things to watch
- **Two sources of rendered-variant truth.** `renderedLength` (Operations) and Step 1's render must agree; extract the COALESCE into one shared SQL fragment or test them against each other explicitly.
- **Smart-reading `query_spec` scope creep** — define the smallest predicate vocabulary the author's stated cases need (tag, profile, date range) and stop; it's JSON, extensible later.
- **Benchmark flakiness on CI-class hardware** — assert ratios with generous tolerance, never absolute ms; keep corpus seeding deterministic (seeded RNG, injected clock).
- **Observation over-firing** — GRDB region tracking is table-grained for raw SQL; use `ValueObservation.tracking` with precise requests where over-firing would wake the whole library on one keystroke (P1's observation-shaped corollary).
- **Missing-row tolerance tests must simulate sync order** (child before parent) with raw SQL fixtures, not ops — ops can't produce those states locally.

**What shipped, step by step** (all in `Sources/VariorumCore/Queries/`, read-only over `Database`, no mutations, no new operations):

1. **`PostRender.swift`** — `Queries.renderPost` (one LEFT-JOIN query, `(position, id)` order): per slot `blockID`/`placementID`/`position`/`variantID?`/`text?`/`activeVariantCount`/`variantLocked`, gap = `variantID == nil`. The variant resolution mirrors `Operations.renderedVariant` exactly — chosen-if-live-and-active-and-same-block (the chosen join goes through the live block row, so a live placement over a missing/tombstoned block is a gap even if the chosen variant row exists), else default-if-live (an *archived* default still renders, matching Operations — archive hides a take from the fan, not from a slot with nothing else to show). Equivalence is pinned by `renderAgreesWithOperationsRenderedVariant`, which runs both resolvers over the same fallback matrix (the plan's "two sources of truth" risk, answered with a test rather than shared SQL — the two are differently shaped: scalar-subselect COALESCE vs LEFT-JOIN COALESCE). `renderedText` joins non-gap texts with `"\n\n"` (`Queries.blockJoinSeparator` — the rendering join that re-creates stored-nothing separators; **decided here per plan, ratify item 1**). Pools render identically (tested). Missing-row tolerance tested with an FK-off fixture database (`unenforcedDatabase` in Support — the only way to materialize child-before-parent sync states locally; production stores always run FKs ON).
2. **`ReadingAssembly.swift`** — `Queries.assembleReading`: curated by `(position, id)` (inner-join membership → a missing/tombstoned post is silently a gap), smart via **`SmartQuerySpec`** (ratify item 3: v1 vocabulary `tags` [ANY-of, subtree semantics], `profile`, `entryDateFrom/To`, AND across fields; NULL spec = all posts, malformed spec = empty, unknown JSON keys ignored), `sort_field`/`sort_dir` (stamp sorts put NULL-stamped rows last in either direction, id tiebreak; smart+`manual` falls back to `created_at ASC` — ratify item 4), `max_posts` LIMIT applied on the read side too (a sync race can overfill a membership; the read renders the extent), and grouping: sectionPath = the **immediate child** of the live grouping root whose subtree contains a live tag applied to the post via a live application, lexically smallest path when several match, computed as a correlated per-post subquery (cost ∝ assembly size); dangling `grouping_tag_id` ⇒ all ungrouped (the AppSpec §7 rule, tested); a post tagged only at the root is ungrouped (ratify item 5). Entries stay in sort order — sectionPath is data on the entry; clustering is the view's presentation choice.
3. **`Lineage.swift`** — `ancestors`/`descendants`: recursive CTE over live `derived_from` edges, `MIN(depth)` collapses diamonds (proven via divide-then-merge), depth-bounded (default 32) so even an impossible cyclic graph terminates (tested with fixture edges), origin excluded; **traversal follows live edges through dead blocks, projection filters to live blocks** (edges may outlive an endpoint under sync — the documented exception; tested with a killed mid-chain block). `derivedBlocks(fromOutlineBlock:inContainer:)` = descendants ∩ live placements (the outline→draft mapping). `versionPeers` matches either side of the canonical pair. `diffPair` returns the two buffers verbatim (whitespace normalization stays a Phase 11 view toggle); nil if either side is dead/missing.
4. **`TagQueries.swift` / `Timeline.swift` / `PoolAndTray.swift`** —
   - Tag subtree by materialized-path prefix using `substr` (never LIKE — no wildcard-injection via tag names; a `art` vs `artifacts` string-prefix trap is tested), correct after `renameTag` (tested incl. mid-tree). `everythingTagged` = the AppSpec §7 UNION as two DISTINCT typed lists (`postIDs`+`blockIDs`), optional subtree widening; live targets and applications only.
   - Timeline: **keyset pagination** over `(stamp, id)` row-value comparison — never OFFSET (P1); a timeline keyed on a stamp lists only rows carrying it (an undated post is not on the entry-date timeline — ratify item 6); `library` is the total listing with `COALESCE(stamp, created_at)` so a never-touched post still shows (same ratify item). Both exclude pools, tombstoned, archived.
   - Pool listing = `renderPost` + block tag paths (one traversal, no bespoke subsystem). **The tray (resolves the KnownIssues entry):** `trayBlocks(postID)` = tombstoned blocks with `last_container_id = postID` that were **not container-cascade victims** — a victim is identified by a same-stamp placement under a same-stamp container, which distinguishes `deleteBlock` (container live, stamp differs) from `deleteContainer` cascades even when a stale `last_container_id` points at the deleted container itself (tested: delete→restore→deleteContainer cycle stays out of the tray; `restoreContainer` is its recovery, verified). Newest deletion first; preview text reads the default variant *through* its tombstone (the tray shows what restore would bring back). Released-then-deleted blocks tray in their release home (Phase 3's stamping fix, verified end-to-end). `unplacedBlocks` = live blocks with no live placement (populated by divideW/merge, emptied by `placeBlock` — tested), deliberately unfiltered by archive (a safety net must not hide things).
5. **`Observations.swift` + `AppDatabase.observe`** — the generic primitive lives on `AppDatabase` (it owns the private writer): `ValueObservation.tracking(fetch).removeDuplicates().values(in:)`, fetches on GRDB's reader queues, values delivered on the cooperative pool (P2 asserted by test: no fetch ever runs on the main thread). Wrappers: `observePost`, `observeReading`, `observeLibrary`, `observePool`, `observeTray`. **Honest note on the plan's over-firing risk:** GRDB region tracking is table-grained for raw-SQL projections (TEXT PKs can't rowid-narrow), so an unrelated write to the same tables re-runs the fetch; `removeDuplicates` guarantees consumers never *see* a spurious emission (tested: an unrelated autosave produces no visible value), and the re-fetch itself stays viewport-shaped because every fetch is P1-shaped. Phase 7 view models must hold observations for on-screen projections only (P3) — noted there, not a new mechanism.
6. **`CorpusFactory` + `PerfBenchmarkTests`** — seeded deterministic corpus built **through Operations** (doubling as a scale smoke test: 10k-block build exercises ~11k operations incl. fans, divides, tags, a 50-post book), fixed-size probes identical in both corpora. Benchmarks assert **ratios** (large ≤ 3× small, with a 2ms noise floor), medians printed to the run log for post-macOS-update comparison. Measured on the M3: `renderPost(50 blocks)` 0.43ms → 0.43ms (1.0×), `assembleReading(50 posts)` 0.43 → 0.43 (1.0×), `timelinePage(50, keyset, second page)` 0.50 → 0.76 (1.5× — duplicate entry-date seeks; well inside tolerance), `tagSubtree` 0.62 → 0.61 (1.0×), `autosave` into a 5-block vs 50-block post 1.25ms vs 1.25ms (flat in post length; the warm-up crossing keeps `renderedLength` off the steady-state path, matching its only-on-crossing design). **P1 asserted, not hoped.** Suite is `.serialized` + `.tags(.perf)`; full suite stays ~7s.

**Interpretations to ratify (logged in `notes/QUESTIONS.md`; none block Phase 5):**
1. **`renderedText` joins blocks with `"\n\n"`** (plan-directed "decide here, document"): the whole-document projection for export/diff. Alternatives were `"\n"` or the merge-style single space; `"\n\n"` re-creates the paragraph break the segmentation doctrine says is never stored. One constant (`Queries.blockJoinSeparator`), trivially changed.
2. **The tray-index schema delta** above.
3. **Smart-reading `query_spec` v1 vocabulary** (PROVISIONAL): `{tags: [path...], profile, entryDateFrom, entryDateTo}`; AND across fields, ANY-of + subtree within `tags`; NULL spec = every post; malformed = empty (fail closed). Extensible JSON — unknown keys ignored.
4. **Smart + `sort_field='manual'` falls back to `created_at ASC`** (PROVISIONAL): the combination is representable in the schema but meaningless (no positions to walk); options were refuse-at-read (crashes views on legal rows) or a deterministic fallback.
5. **Grouping semantics** (PROVISIONAL): section = immediate child of the grouping root, subtree containment, lexically-smallest tiebreak, root-only tags ungrouped, assembly order preserved (clustering is presentation). Options considered: full-path sections (leaks depth), first-created tiebreak (nondeterministic under sync).
6. **Timeline vs library NULL-stamp handling** (PROVISIONAL): a stamp timeline lists only stamped rows; `library` COALESCEs to `created_at` so nothing hides. The alternative (COALESCE in timelines too) silently interleaves "created" with "edited" semantics on a surface named for one stamp.
7. **Archived containers are out of *ambient* view at read time** (PROVISIONAL — the specs define archive only as "kept, out of view"): excluded from reading assembly (curated AND smart), timeline, and library; still rendered when directly addressed (`renderPost` of the post itself) and still found by `everythingTagged` (a lookup tool, not an ambient view). The curated-exclusion follows the archived-*chosen-variant* precedent (an explicit pointer does not override archive; AppSpec §7). Alternative reading — curated membership shows archived posts — is a one-line filter flip. Blocks: `renderPost` deliberately does **not** filter `block.archived_at`, matching `Operations.renderedVariant`/`renderedLength` exactly (the phase's reuse instruction); no operation can archive a block today, so the state is unreachable.
