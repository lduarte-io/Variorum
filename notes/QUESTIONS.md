# Variorum — Open Questions for the Author

Format per entry: **date · phase · question · options considered · PROVISIONAL call made (if any) · status (open / answered → where recorded)**

1. **2026-07-06 · Phase 7 · When does the open tail begin?** AppSpec §7's type-time crystallization needs a moment where fresh end-of-post text stops being "the last block" and starts being "the open tail" — the spec doesn't name the gesture. Options: (a) **Enter at the exact document end opens the tail** (typed single newline only; paste/Enter anywhere else stays block content per I4); (b) Enter at the last block's end appends a content newline — but then crystallization is unreachable for any non-empty post (the post becomes one growing block); (c) a double-Enter gesture. **PROVISIONAL: (a)** — the only reading that makes the spec's "each completed paragraph becomes a block as you type past it" reachable in the normal flow. Consequence to ratify: multi-paragraph blocks can't be *typed* at the post end in paragraph mode (paste-into-block, one-block posts, and Phase 3's merge still produce them — arguably exactly the spec's segmentation intent). Tested as `BlockRangeIndexTests.enterAtDocumentEndOpensTheTail` and siblings. **Status: open.**

2. **2026-07-06 · Phase 7 · Open-tail persistence timing.** The trailing paragraph still being typed is "an open tail, not yet a block" (AppSpec §7) — so its text lives only in the editor buffer until typed past. Implemented: the tail crystallizes on typing past (spec), **and on editor teardown** (post switch, window close, ⌘Q via `applicationShouldTerminate`) so a normal exit never loses it. Loss window: a hard crash/force-quit can lose the trailing un-typed-past paragraph only. Options considered: teardown-only (**PROVISIONAL — spec-literal**: the paragraph "is not yet a block", and minting earlier would birth blocks at a moment the spec says they don't exist); idle-mint after a quiet period (bounded crash loss, earlier block birth — cheap to add if wanted); scratch-table persistence (rejected: no schema slot — inventing one is a product call). **Status: open.**

3. **2026-07-06 · Phase 7 · Sentence-mode type-time crystallization** (the standing KnownIssues item, due at this checkpoint per the phase plan). The editor now exists: while typing in a sentence-mode post, crystallization currently fires per completed *paragraph* (the spec's letter; `SegmentationRules.crystallizedBoundary` is deliberately mode-less), while *bulk paste* into the tail segments per sentence (`bulkSegments(.sentence)`). Should live typing in sentence-mode posts crystallize per completed sentence instead? The editor is in hand to try both. **Status: open — author call, never decided autonomously.**
