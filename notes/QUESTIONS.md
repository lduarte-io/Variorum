Batched author-only calls and PROVISIONAL ratifications from `/run-phase` coordinator sessions (see the Autonomous phase execution amendment in `CLAUDE.md`). Each checkpoint report walks this list; answered items get their resolution recorded in the owning phase plan's closeout (and, when the author makes a spec-level call, as an author-decision delta in `notes/AppSpec.md` §14) and are then removed.

Format per entry: **date · phase · question · options considered · PROVISIONAL call made (if any) · status (open / answered → where recorded)**

1. **2026-07-06 · Phase 5 · May sync land conflict/rescue variants under a SEALED post?** The post seal refuses everything under the post (author-ratified 2026-07-05, incl. fan growth) — but refusing a conflict variant would throw the losing text away, violating S5's "nothing is ever clobbered", and would wedge sync on sealed posts. Options: (a) land it — S5 outranks the seal; a sync conflict is not authoring (chosen, PROVISIONAL; `Operations.resolveSyncConflict` + the engine's rescue path); (b) refuse and drop the text; (c) park losing texts somewhere outside the sealed post (a new mechanism). **Status: open.**

2. **2026-07-06 · Phase 5 · The archive/archive race (I10 by another door).** Two devices each archive a *different* last-active variant of one block; tombstone-style resurrection (SyncSpec §7) doesn't apply — nothing is tombstoned — yet the block converges to zero live active variants. Options: (a) extend the I10 repair doctrine: un-archive the archived variant with the highest `server_seq`, label `'rescued'` (chosen, PROVISIONAL — deterministic, never a takeless block); (b) tolerate the state and teach every read surface about it; (c) treat it as block death (contradicts both devices' intent — rejected by §7's own reasoning). **Status: open.**

3. **2026-07-06 · Phase 5 · Ratify the `sync_row_seq` client-machinery table (SyncSpec §3 delta).** §7's repairs rank rows by `server_seq` ("higher wins", "highest"), which requires the client to KNOW per-row seqs; §3's machinery list has no home for that knowledge. Shipped as local-only migration `v1_3` (own commit `d280ffe`), written on push-accept and pull-apply; **rows the server never accepted rank as seq 0** (a never-accepted row carries no later-intent authority — the deterministic reading of "later intent"). Ratify the table + the seq-0 rule into SyncSpec §3/§7. **Status: open.**

4. **2026-07-06 · Phase 5 · Ratify the orphan repair (SyncSpec §7 addition).** Cascades cannot cross devices: a parent tombstone applying locally fires the cascade with outbox triggers muted (children the deleter never saw die silently → divergence), and live children can arrive under locally-dead parents. Shipped: (1) a live→dead parent transition explicitly enqueues its stamp-matched cascade victims whose tombstones the batch is not delivering; (2) a live child arriving under a locally-dead parent joins the parent's cascade with the parent's **exact stamp** (so `restoreContainer`/`restoreBlock` still revive it — tested: a phone entry written into a concurrently-deleted post dies everywhere AND comes back with the post). Alternative considered: tolerate one-sided live orphans (diverges; rejected — the convergence suites' byte-equality is the phase's contract). **Status: open.**

5. **2026-07-06 · Phase 5 · Small delta from SyncSpec §5's letter: a merged row that equals the server row wholesale has its outbox entry cleared** (spec says "keep it enqueued"). Keeping it enqueued ships a no-op push, bumps the version, and echoes to every device; clearing is convergence-neutral (quiescence proven either way) and quieter. One line to flip if the letter is preferred. **Status: open.**
