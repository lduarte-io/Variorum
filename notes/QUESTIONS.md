1. **2026-07-06 · Phase 7 · When does the open tail begin?** AppSpec §7's type-time crystallization needs a moment where fresh end-of-post text stops being "the last block" and starts being "the open tail" — the spec doesn't name the gesture. Options: (a) **Enter at the exact document end opens the tail** (typed single newline only; paste/Enter anywhere else stays block content per I4); (b) Enter at the last block's end appends a content newline — but then crystallization is unreachable for any non-empty post (the post becomes one growing block); (c) a double-Enter gesture. **PROVISIONAL: (a)** — the only reading that makes the spec's "each completed paragraph becomes a block as you type past it" reachable in the normal flow. Consequence to ratify: multi-paragraph blocks can't be *typed* at the post end in paragraph mode (paste-into-block, one-block posts, and Phase 3's merge still produce them — arguably exactly the spec's segmentation intent). Tested as `BlockRangeIndexTests.enterAtDocumentEndOpensTheTail` and siblings. **Status: open.**

2. **2026-07-06 · Phase 7 (review round) · Is text drag-drop into the open tail bulk entry or typing?** AppSpec §7 names bulk entry as "paste, import, pool-drop, mobile capture"; the editor arms bulk segmentation on *paste* only, so text **dropped** into the tail routes as typing (accumulates as tail text; paragraph crystallization applies). A multi-paragraph drag is arguably bulk-shaped. **PROVISIONAL: the typing reading stands** (the spec's list doesn't name drag-drop; the difference only shows for multi-paragraph drops, and Phase 9's gesture work — where drag interactions grow — is the natural place to revisit). **Status: open.**

3. **2026-07-06 · Phase 7 (review round) · A sealed post with an open tail at teardown/quit.** If a post is sealed remotely while the editor holds an open tail, the teardown/idle mint refuses (`lockedPost`). Current behavior: the refusal is **surfaced** (status message) and the text stays in the editor buffer for the session — but on ⌘Q it is gone after the message. Anything stronger is a product call: (a) refuse/delay quit until the author resolves; (b) a conflict-variant-style rescue (mint the tail into an unsealed container — inventing a rescue path, S5-adjacent but NOT S5); (c) park in `container.floating_notes` (also under the seal, so refused anyway). **PROVISIONAL: surface-only** — the seal's whole point is refusing writes, and inventing a rescue container is exactly the class of behavior CLAUDE.md reserves for the author. Note: with idle-mint (her mid-phase ruling) the window is seconds wide — the tail is normally already a block before a quit can race a remote seal. **Status: open.**
