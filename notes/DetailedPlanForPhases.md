# Variorum — Detailed Plan for Phases (Master Plan)

This is the master build plan. It holds: the phase table, the **current phase pointer**, and the **most recently closed phase's** one-paragraph closeout — all earlier closeouts and every superseded pointer live VERBATIM in `notes/PhaseCloseoutArchive.md` (the 2026-08-01 lean-docs rule, the author's call on the Fragments precedent; AppSpec §14 rolls its dated deltas into `notes/AppSpecDeltaArchive.md` the same way). Per-phase execution plans live in `notes/plans/`, written **just-in-time, one phase ahead** — never plan the whole app up front. The closeout of phase N is the starting context for phase N+1.

**Workflow rules** (also in `CLAUDE.md`): every step in an execution plan has tests; tests run at the END of a step/phase, never at the start of a session (the previous closeout is the baseline); schema/model changes get their own commit; deferred work goes to `KnownIssuesAndTechDebt.md` only with an owning phase named. **Closeout of phase N includes writing phase N+1's execution plan AND a kickoff message** (at the top of that plan file) that a fresh session can start from — and, since 2026-08-01, **rolling the newly superseded pointer, the previous phase's closeout paragraph, and AppSpec §14's outgoing delta into their archives** in the same commit.

## Sequencing rationale (why this order)

- **Schema before operations before UI** — correctness lives in the operations layer; the editor is a client of it.
- **Sync machinery is in schema v1** (author's direction: sync is early, not commercial-phase). Retrofitting outbox triggers, `sync_version`, and fractional-index positions after tables exist would mean migrating live data; a week of design now beats that forever.
- **Structural ops (3) before sync (5):** every write pattern the server will mirror gets proven locally first — schema flaws surface while migrations are still free, not after Postgres mirrors the schema in lockstep.
- **Sync (5) before the editor (7):** all UI code is born onto a sync-aware persistence layer (apply mode, outbox, repairs live from the start) — no retrofits — and the moment iOS capture (8) exists, the author starts journaling for real.
- **The TK2 spike (6) before the editor (7)** — `notes/TEXTKIT2_NOTES.md` §2 documents viewport/height/scroll-to-location as the stack's least reliable subsystem; the facts must be learned *on Tahoe* before book-scrub is designed onto them. Xcode 26 on both machines is this phase's hard prerequisite.
- **iOS capture (8) immediately after editor v1** — the author's stated priority: journal from the phone early, use the product while building it. Real daily use is also the best sync soak test.
- **Views split into first (10) and remaining (11)**; **UI design (13) after hardening (12)** — substrate first, beauty later, with the author; **accounts (14) reuse the same sync protocol.** *(The 13/12 half superseded 2026-07-17 — 13 now precedes 12: the hardening evidence requires the real daily use that only a usable app generates; the pointer's deferral paragraph is the record.)*
